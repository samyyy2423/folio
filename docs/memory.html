What it's for

Memory as C has it: numbers kept as C keeps them, in bytes or in memory of the program's own, outside the collector, for file formats, what goes over a network, a model's weights and what a C library hands back. A kind of number is named as a library's line names it: "a byte", "a signed byte", "a short whole number", "an unsigned short whole number", "a whole number", "an unsigned whole number", "a long whole number", "an unsigned long whole number", "a pointer", "a float" and "a number" (C's double). Places count from 1, as bytes' do.

use "memory.folio" as memory
set b to 16 bytes
memory's put(b, 1, -2, "a whole number")                # 4 bytes, as C keeps an int
say b                                                   # (16 bytes: 254, 255, 255, 255, 0, ...)
say memory's get(b, 1, "a whole number")                # -2
say memory's get(b, 1, "an unsigned whole number")      # 4294967294: the same bytes, read unsigned
memory's put(b, 5, 0.1, "a float")                      # rounded to the nearest float, as C rounds it
say memory's get(b, 5, "a float")                       # 0.100000001490116
memory's put(b, 9, 258, "a short whole number", "big")  # biggest byte first, as networks send them: 1, 2
memory's put_many(b, 1, (list of 1, 2, 3), "a short whole number")
say memory's get_many(b, 1, 3, "a short whole number")  # [1, 2, 3]
say memory's size_of("a long whole number")             # 8

set block to memory's take(4096)          # 4,096 bytes of the program's own, outside the collector, all 0
memory's put(block, 1, 7, "a long whole number")
memory's copy(b, 1, block, 9, 16)         # 16 bytes, from b's 1st on to block's 9th on
memory's fill(block, 100, 8, 255)         # 8 bytes from the 100th on, each 255
say memory's address_of(block)            # where it is, for a library's `a pointer`
memory's give_back(block)                 # its memory back to the system; using it after is a mistake

Every place is checked against the memory's size, and every number against its kind: a whole number in its kind's range, or a fail with that says so. get_many and put_many take a list of numbers in one go. size(m) is how many bytes m has, and block_at(address, size) is memory a C library gave as a block, which give_back doesn't take. "little", the order every computer Folio runs on keeps numbers in, can be said too.

C's structures, by their fields' names, laid out as C lays them out (each field on a boundary of its own size, the whole a multiple of its largest), and memory a part at a time:

set point to memory's layout(list of "x", "a whole number", "y", "a whole number", "weight", "a number")
say memory's size_of(point)                          # 16: 4, 4, then 8 on a boundary of 8
memory's put_field(block, 1, point, "y", 7)           # a point at block's 1st byte, its y 7
say memory's get_field(block, 1 + memory's size_of(point), point, "weight")   # the next point's weight
set part to memory's view(block, 17, 16)              # 16 of block's bytes, from its 17th: places from 1
set safe to memory's read_only(part)                  # the same bytes, which put and the rest refuse
say memory's taken()                                  # bytes taken and not given back, to find a leak

Numbers threads share, each change whole however many threads make one at once (64-bit whole numbers on an 8-byte boundary, as the processor's lock instructions have them): add_atomically(m, place, n) gives what was there before, swap_if(m, place, was, now) puts now there if was was there and says whether it did, and get_atomically and put_atomically. A view is gone once what it's a view of is given back.

In a program folio build makes, get, put and their many go through a loop of Folio's own in machine code (DESIGN §160), and take, give_back, copy and fill through the system's C library (msvcrt on Windows, libc on Linux), so such a program is run or built with --allow-libraries to take memory. On the JavaScript engines, which have no memory but the collector's, a block is bytes, and address_of and block_at are a fail with. A block's memory is the program's until give_back, however long that is, and an address that isn't one, given to block_at, can crash the program, as in C.
