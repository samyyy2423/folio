Read and write CSV

text.folio reads CSV the way spreadsheets write it, quotes and commas inside them included, and writes it back. csv_rows gives a list of rows, each a list of text; csv_text makes CSV from rows.

use "text.folio" as text

set rows to list of (list of "name", "city", "score"), (list of "Ada", "London", 91), (list of "Lee, Ana", "Lisbon", 78)
write text's csv_text(rows) to "scores.csv"

set table to text's csv_rows(read "scores.csv")
for each row in items 2 to (length of table) of table
    say item 1 of row + " from " + item 2 of row + " scored " + item 3 of row
end
Ada from London scored 91
Lee, Ana from Lisbon scored 78

Every value comes back as text. number of makes a number of one, so the scores can be added up:

use "text.folio" as text

set table to text's csv_rows("name,score\nAda,91\nLee,78\nSam,85")
set total to 0
for each row in items 2 to (length of table) of table
    add number of item 2 of row to total
end
say "average: " + (total / (length of table - 1) with 1 decimals)
average: 84.7

Read, change and write JSON

json's parse turns JSON into Folio's own values: an object becomes a dictionary, an array a list, true and false yes and no, and null nothing. as json turns any of them back.

use "json.folio" as json

set order to json's parse("\{\"id\": 7, \"items\": [\{\"name\": \"tea\", \"price\": 3.5}, \{\"name\": \"cake\", \"price\": 4.25}]}")
set total to 0
for each thing in item "items" of order
    set total to total + item "price" of thing
end
say "order " + item "id" of order + " costs " + total

set item "total" of order to total
write order as json to "order.json"
say read "order.json"
order 7 costs 7.75
{"id":7,"items":[{"name":"tea","price":3.5},{"name":"cake","price":4.25}],"total":7.75}

A mistake in the JSON is a fail with that says where it is, so try can catch it:

use "json.folio" as json

try
    set data to json's parse("\{\"name\": \"Sam\",}")
if it fails with why
    say "not JSON: " + why
end
not JSON: JSON, letter 16: expected a key in quotes but found }

Call a web API

read reads a site as well as a file. With json's parse, that's a JSON API in two lines. A program that reaches the network asks first, unless it runs with --allow-net: folio run --allow-net stars.folio.

use "json.folio" as json

set repo to json's parse(read "https://api.github.com/repos/samyyy2423/folio")
say item "full_name" of repo + " has " + item "stargazers_count" of repo + " stars"

For more than a GET (other methods, headers, a body of JSON, a status to check), http.folio has them all. It runs on sockets of its own, so it needs --allow-libraries too:

use "http.folio" as http

set answer to http's post("https://httpbin.org/post", record with name "Sam", score 91)
http's check(answer)
say status of answer
say text of answer

A web API with a database

server.folio gives each request to a function of the program's, which says what to send back: text, a list or dictionary as JSON, or a record with a status. sqlite.folio keeps the data in a file. Together they're a small API that lists and saves notes:

use "server.folio" as web
use "sqlite.folio" as sqlite

set db to sqlite's open("notes.db")
sqlite's run(db, "create table if not exists notes (id integer primary key, text text)")

to answer with request
    if path of request is "/notes" and method of request is "GET"
        return sqlite's query(db, "select id, text from notes order by id")
    end
    if path of request is "/notes" and method of request is "POST"
        sqlite's run_with(db, "insert into notes (text) values (?)", list of body of request)
        return record with status 201, body "saved"
    end
    return record with status 404, body "There's nothing at " + path of request
end

web's serve(8080, answer)

Run it with folio run --allow-libraries --allow-read --allow-write notes.folio, then try it: curl -d "buy milk" localhost:8080/notes saves a note, and curl localhost:8080/notes lists them as JSON.

The server answers many people at once, and web's serve_on_workers(8080, answer, 4) answers on 4 cores. folio build notes.folio --allow-libraries --allow-read --allow-write makes it a program of its own, to copy to a server and run.

A command-line tool

options.folio reads a program's command line as Python's argparse does: options with values, flags, names in order, and a --help made from what each is for. In a real program, parse is given arguments, what the program was run with; here it's given a list, so the recipe can show what it does.

use "options.folio" as options

set p to options's parser("greet", "Says hello to someone.")
options's option(p, "name", "n", "who to greet", "World")
options's option(p, "times", "t", "how many times", 1)
options's flag(p, "loud", "l", "shout it")

set given to options's parse(p, list of "--name", "Sam", "-t", "2", "--loud")
for each k from 1 to item "times" of given
    set greeting to "Hello, " + item "name" of given + "!"
    if item "loud" of given
        set greeting to uppercase of greeting
    end
    say greeting
end
HELLO, SAM!
HELLO, SAM!

What --help says comes from the same lines:

use "options.folio" as options

set p to options's parser("greet", "Says hello to someone.")
options's option(p, "name", "n", "who to greet", "World")
options's flag(p, "loud", "l", "shout it")
say options's help_text(p)
usage: greet [-h] [-n NAME] [-l]

Says hello to someone.

options:
  -h, --help            say this, and stop
  -n, --name NAME       who to greet (World if it isn't given)
  -l, --loud            shout it

folio build greet.folio makes it a program of its own: greet --name Sam --loud.

Numbers, statistics and a chart

stats.folio has what Python's statistics module has, and charts.folio draws bars and lines to SVG or PNG. A week of temperatures, summed up and drawn:

use "stats.folio" as stats
use "charts.folio" as charts

set days to list of "Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"
set temperatures to list of 12.5, 14, 13.2, 17.8, 19.4, 21, 18.6

say "mean " + (stats's mean(temperatures) with 1 decimals) + "°C"
say "median " + stats's median(temperatures) + "°C"
say "standard deviation " + (stats's stdev(temperatures) with 2 decimals)
set warmest to 1
for each k from 2 to length of temperatures
    if item k of temperatures is greater than item warmest of temperatures
        set warmest to k
    end
end
say "warmest " + item warmest of temperatures + "°C, on " + item warmest of days

charts's save(charts's line_chart("A week of temperatures", days, temperatures), "week.svg")
say "drew week.svg"
mean 16.6°C
median 17.8°C
standard deviation 3.36
warmest 21°C, on Sat
drew week.svg

Numbers in Folio are decimals compared to 15 digits, as a spreadsheet keeps them, so money adds up as it should:

set prices to list of 0.1, 0.2, 19.99
set total to 0
for each p in prices
    set total to total + p
end
say total
say 0.1 + 0.2 is 0.3
20.29
yes

Dates

dates.folio reads dates, adds days, counts the days between two, and writes a date as a person wants it.

use "dates.folio" as dates

set start to dates's read_date("2026-11-05")
set due to dates's add_days(start, 30)
say "due " + dates's format_date(due, "dddd D MMMM YYYY")
say dates's days_between(start, due) + " days from " + dates's format_date(start, "ddd D MMM")
say "a weekend day: " + (dates's format_date(due, "ddd") is in list of "Sat", "Sun")
due Saturday 5 December 2026
30 days from Thu 5 Nov
a weekend day: yes

dates's now() is the date and time it is now, and format_date writes hours, minutes and seconds too: dates's format_date(dates's now(), "YYYY-MM-DD hh:mm:ss").

Work on every core

start f(x) on another core runs a call on a worker, a thread with memory of its own, and wait for gives back what it gave. Workers share nothing (each gets copies), so they can't trip over each other. In a program folio build makes, they run at the same moment on every core; in the playground they run one after another and give the same answers.

to primes_below with top
    set found to 0
    for each n from 2 to top - 1
        set prime to yes
        set d to 2
        repeat while d * d is at most n and prime
            if remainder of n divided by d is 0
                set prime to no
            end
            add 1 to d
        end
        if prime
            add 1 to found
        end
    end
    return found
end

set jobs to empty list
for each top in list of 1000, 2000, 3000, 4000
    add (start primes_below(top) on another core) to jobs
end
for each job in jobs
    say wait for job
end
168
303
430
550

tools/cores.folio does the same for a whole list at once, across separate copies of the program.

Test a program

Tests are functions whose names start with test_, in a file whose name ends in .test.folio. Each runs on its own, and expect says what should be so; when it isn't, the mistake says what each side was.

to with_tax with price
    return price * 1.2
end

to test_tax_on_ten
    expect with_tax(10) is 12
end

to test_tax_on_nothing
    expect with_tax(0) is 0
end

to test_tax_on_pennies
    expect with_tax(0.1) is 0.12
end

Save it as prices.test.folio, and folio test runs every test file in the folder and the folders inside: ✓ test_tax_on_ten, and so on, then how many passed. folio coverage runs them too, and says which lines no test ran.

A test can check a mistake as well, with try:

to price_of with item_name
    if item_name is "tea"
        return 3.5
    end
    fail with "there's no " + item_name + " on the menu"
end

to test_an_unknown_item
    try
        price_of("soup")
        expect no
    if it fails with why
        expect why is "there's no soup on the menu"
    end
end

Find and change text

text.folio's patterns are regular expressions: \d a digit, \w a letter, digit or _, + one or more, and the rest. In Folio's own text, a \ is written \\.

use "text.folio" as text

set log to "2026-11-05 ERROR disk full\n2026-11-05 INFO started\n2026-11-06 ERROR no network"
for each line in split log by "\n"
    if text's contains_pattern("ERROR", line)
        say text's replace_all("^[\\d-]+ ERROR ", line, "problem: ")
    end
end

say text's matches("^[a-z.]+@[a-z]+\\.[a-z]+$", "ada.l@folio.dev")
set found to text's find("(\\d+) of (\\d+)", "page 12 of 40")
say item 1 of groups of found + " and " + item 2 of groups of found
problem: disk full
problem: no network
yes
12 and 40

Counting words needs no library at all: a dictionary keeps a count for each.

set counts to empty dictionary
for each word in split (lowercase of "The folio and the lamp and the night") by " "
    if word is in counts
        set item word of counts to item word of counts + 1
    else
        set item word of counts to 1
    end
end
say counts
(dictionary where "the" is 3, "folio" is 1, "and" is 2, "lamp" is 1, "night" is 1)
