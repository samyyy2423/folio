What it's for

PostgreSQL, as Python's psycopg has it: connected over its own protocol (version 3), logged in with SCRAM-SHA-256 or MD5, over TLS where asked for; queries with their values as parameters, sent apart from the SQL so no value is ever read as SQL; rows as dictionaries, each value as Moth has it; and transactions. On sockets.moth: a program moth build makes can use it, built with --allow-libraries.

use "postgres.moth" as pg
set db to pg's connect(record with host "localhost", port 5432, user "app", password "secret", database "shop")
set db to pg's connect_url("postgres://app:secret@db.example.com/shop?sslmode=require")
for each row in pg's query(db, "select id, name from people where age > $1 and city = $2", list of 21, "Pune")
    say item "id" of row " " item "name" of row
end
say pg's query_one(db, "select count(*) as n from people")    # the first row, or nothing if none
say pg's execute(db, "update people set name = $1 where id = $2", list of "Sam", 7)   # how many it changed
to move_money with db
    pg's execute(db, "update accounts set total = total - 10 where id = $1", list of 1)
    pg's execute(db, "update accounts set total = total + 10 where id = $1", list of 2)
end
pg's in_transaction(db, move_money)           # all or none: COMMIT, or ROLLBACK and the mistake again
pg's run_script(db, read "schema.sql")         # many statements, with no parameters
pg's close(db)

connect's record has host, port (5432), user, password, database (the user's name), tls ("prefer": TLS if the server has it and its certificate can be checked, "require": checked TLS or a mistake, "disable": never) and trust (a PEM file of certificates to trust besides the system's, as a cloud's own CA, or nothing); each but user can be left out. TLS always checks the server's certificate, for its name. Parameters are $1, $2 ... in the SQL: text, numbers, yes and no, nothing (NULL), bytes (bytea), and lists, dictionaries and records (as JSON). Values come back as text, numbers (integers, floats and numeric), yes and no, nothing, bytes (bytea), what JSON says (json and jsonb), and lists (arrays of those); dates and times stay text, as PostgreSQL writes them ("2026-11-04 10:15:00"). A query PostgreSQL refuses is a fail with with its message and code, as "PostgreSQL said: relation \"nowhere\" does not exist (42P01)".
