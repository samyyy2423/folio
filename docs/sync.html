What it's for

Tasks taking turns, as Python's threading, queue and concurrent.futures have it: a lock that one task holds at a time, a semaphore that a few can, a flag that tasks wait to see raised, a queue that one task sends to and another takes from, and many calls run as tasks. In Folio alone, so it works everywhere.

use "sync.folio" as sync
set guard to sync's lock()
set balance to 0
to deposit with amount
    sync's take(guard)
    set balance to balance + amount     # one task at a time in here
    sync's let_go(guard)
end

set jobs to sync's queue()              # or queue_holding(10): send waits while 10 are waiting
to worker
    repeat while yes
        set job to sync's receive(jobs)     # waits for one
        if job is nothing
            return "done"
        end
        deposit(job)
    end
end
set w to start worker()
sync's send(jobs, 5)
sync's send(jobs, nothing)
say wait for w                          # done

say sync's run_each(slow_square, list of 1, 2, 3)   # [1, 4, 9]: a task for each, waited for in order

take_within(lock, 50) waits at most 50 milliseconds and says whether it took the lock; receive_within(queue, 50) fails, with "nothing came in 50 milliseconds", if nothing came. A flag is raised and lowered, and wait_for_flag waits until it's raised. wait_for_all(jobs) gives what each task gave, and wait_for_any(jobs) the first of them to end. job has ended asks without waiting.

Workers (start f(x) on another core, DESIGN §124) share nothing: each is given copies, so a lock, flag or queue given to one, or among the program's variables it starts with, is its own, and keeps its own tasks in step. wait_for_all and wait_for_any take workers as they take tasks.

One task runs Folio at a time, and a task only lets the others run at a loop's end, a call or a wait, so what's between those happens with nothing else running: a lock is taken by seeing it's free and marking it held, with nothing in between. That's why take and receive do their work themselves, with no call. On the JavaScript engines a task runs to its end when it's started, so a task there that waits for what the program does after starting it waits for ever, and take_within and receive_within give up when their time is up.
