What it's for

JSON Web Tokens (RFC 7519), as Python's PyJWT has them: made and checked with a shared secret (HS256, HS384, HS512), and checked with an RSA public key (RS256, RS384, RS512), in PEM or as a JWK, as identity providers sign them. In Moth alone, so it works everywhere, but for the clock: now(), and verify when it isn't given now, ask the system's clock through its C library, so a program moth build makes that uses them is built with --allow-libraries; and in the playground, where no library loads, verify is given now.

use "jwt.moth" as jwt
set token to jwt's make((dictionary where "sub" is "42", "exp" is jwt's now() + 3600), "a long random secret")
set claims to jwt's verify(token, "a long random secret")   # its claims, or a mistake if it isn't good
say item "sub" of claims
set claims to jwt's verify(token, read "public.pem", record with issuer "https://id.example.com", audience "my-app")
set claims to jwt's verify(token, key)        # a JWK: a dictionary with kty "RSA", n and e, as a JWKS lists
set token to jwt's make(claims, secret, "HS512", dictionary where "kid" is "2026-11")   # another algorithm, a kid
set parts to jwt's decode(token)               # its header and claims, NOT checked: to look at, never to trust
set key to jwt's read_key(read "public.pem")   # an RSA key's n and e (as big.moth has them), and size in bytes

verify checks the signature first, with an algorithm of the key's kind: a secret (text or bytes, or a JWK of kty "oct") only with HS256, HS384 or HS512; an RSA key (a PEM public key, RSA public key or certificate, or a JWK of kty "RSA") only with RS256, RS384 or RS512. So a token can't choose "none", nor HMAC with a public key as its secret. Then its claims: exp (the moment it ends) and nbf (the moment it starts), in seconds since 1970, give or take leeway seconds for clocks that differ; iat isn't after now; iss is issuer, if one's given; and if the token has an aud, audience is one of them. Its options, a record or dictionary, can have any of issuer, audience (each text or a list), leeway (0), require (claims it must have, as list of "exp", "iss"), algorithms (those allowed, as list of "RS256") and now (the time to check against, for tests). A token that isn't good is a fail with that says why: catch it with try.
