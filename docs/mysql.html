What it's for

MySQL and MariaDB, as Python's PyMySQL has them: connected over their own protocol, logged in with caching_sha2_password (MySQL 8's), sha256_password or mysql_native_password, over TLS where asked for; prepared statements with their values as parameters, sent apart from the SQL so no value is ever read as SQL; rows as dictionaries, each value as Moth has it; and transactions. On sockets.moth: a program moth build makes can use it, built with --allow-libraries.

use "mysql.moth" as mysql
set db to mysql's connect(record with host "localhost", port 3306, user "app", password "secret", database "shop")
set db to mysql's connect_url("mysql://app:secret@db.example.com/shop?ssl-mode=REQUIRED")
for each row in mysql's query(db, "select id, name from people where age > ? and city = ?", list of 21, "Pune")
    say item "id" of row " " item "name" of row
end
say mysql's query_one(db, "select count(*) as n from people")     # the first row, or nothing if none
say mysql's execute(db, "update people set name = ? where id = ?", list of "Sam", 7)   # how many it changed
set done to mysql's run(db, "insert into people (name) values (?)", list of "Ana")
say last_id of done                             # the AUTO_INCREMENT it made; rows, count and columns too
mysql's in_transaction(db, move_money)          # all or none: COMMIT, or ROLLBACK and the mistake again
mysql's run_script(db, read "schema.sql")       # many statements, with no parameters
mysql's close(db)

connect's record has host, port (3306), user, password, database (or none), tls ("prefer": TLS if the server has it and its certificate can be checked, "require": checked TLS or a mistake, "disable": never) and trust (a PEM file of certificates to trust besides the system's); each but user can be left out. Without TLS, caching_sha2_password and sha256_password send the password encrypted with the server's RSA key. Parameters are ? in the SQL: text, numbers, yes and no, nothing (NULL), bytes, and lists, dictionaries and records (as JSON). Values come back as text, numbers (integers, floats and decimals), nothing, bytes (binary columns), and what JSON says (JSON columns); dates and times are text, as "2026-11-04 10:15:00". A statement MySQL refuses is a fail with with its message, code and state, as "MySQL said: Table 'shop.nowhere' doesn't exist (1146, 42S02)".
