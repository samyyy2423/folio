What it's for

Redis (and the servers that speak its protocol: Valkey, KeyDB, Dragonfly), as Python's redis package has it: keys with values that can end, numbers counted up, lists, hashes, publishing and subscribing, many commands sent at once (pipelining) or all or none (MULTI and EXEC), logged in and over TLS, in RESP2 or RESP3, on sockets.folio. A program folio build makes can use it, built with --allow-libraries.

use "redis.folio" as redis
set r to redis's connect("localhost", 6379)        # connect_secure for TLS; connect_url("rediss://:pw@host:6380/2")
redis's log_in(r, "a password")                    # or log_in(r, "a password", "a user"), for Redis 6's users
redis's put(r, "greeting", "hello")                # SET
redis's put_for(r, "session:42", "data", 3600)     # gone in an hour
say redis's get(r, "greeting")                     # hello; nothing if there's no such key
say redis's increment(r, "visits")                 # 1, then 2, ...
redis's expire(r, "greeting", 60)
say redis's time_left(r, "greeting")               # seconds: -1 if it never ends, -2 if there's no such key
redis's push(r, "jobs", "first")                   # to the end; push_front; pop and pop_back take one off
say redis's list_items(r, "jobs")                  # every item; list_length counts them
redis's hash_put(r, "user:7", "name", "Sam")       # hash_get, hash_all (a dictionary), hash_remove
say redis's command(r, list of "SET", "k", "v", "NX", "EX", 10)   # any command, as its words
say redis's pipeline(r, list of (list of "INCR", "a"), (list of "GET", "a"))   # sent at once: each reply
say redis's transaction(r, list of (list of "INCR", "a"), (list of "INCR", "b"))   # MULTI ... EXEC
redis's publish(r, "news", "hello")                # how many got it
redis's subscribe(r, list of "news")               # a connection of its own, then:
set m to redis's next_message(r)                   # (record with channel "news", message "hello", pattern nothing)
redis's use_resp3(r)                               # RESP3: maps come back as dictionaries, doubles as numbers

Replies are Folio's own values: text, numbers, nothing, lists, and in RESP3 dictionaries, yes and no. Bulk strings come back as text; get_bytes and command_bytes keep them as bytes. What's sent is text (its UTF-8), bytes, or numbers. An error the server sends is a fail with, as "Redis said WRONGTYPE Operation against a key holding the wrong kind of value".
