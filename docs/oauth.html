What it's for

OAuth 2 clients (RFC 6749), as Python's requests-oauthlib and Authlib have them: signing a person in with the authorization code flow and PKCE (RFC 7636), which a program on the command line does with a server of its own on 127.0.0.1 for the browser to come back to (RFC 8252); a program's own tokens, with its client credentials; and tokens refreshed before they end. Over http.moth and server.moth: a program moth build makes can use it, built with --allow-libraries (and --allow-run, to open the browser itself).

use "oauth.moth" as oauth
set github to oauth's provider("https://github.com/login/oauth/authorize", "https://github.com/login/oauth/access_token", "my-client-id")
set google to oauth's discover("https://accounts.google.com", "my-client-id")   # its endpoints, from OpenID Connect
set tokens to oauth's sign_in(google, list of "openid", "email")   # the browser opens; the person signs in
say access_token of tokens            # and refresh_token, expires_at, scope, id_token, token_type, fields
if oauth's expired(tokens)            # within a minute of its end
    set tokens to oauth's refresh(google, tokens)
end
set service to oauth's provider("", "https://id.example.com/oauth/token", "my-service")
set client_secret of service to "the service's secret"
set tokens to oauth's client_credentials(service, list of "reports.read")   # no person: the program's own

set started to oauth's authorization_start(google, "https://my.app/callback", list of "openid")   # a web app's:
# send the browser to url of started, keep state and verifier of started, and when it comes back,
set tokens to oauth's exchange_code(google, code, "https://my.app/callback", verifier of started)

A provider is a record: authorize_url, token_url, client_id, client_secret (nothing for a public client, as a program on a person's computer is), secret_in ("basic", sent as HTTP Basic, or "body", in the form), port (where sign_in's own server listens first, 8765; the next free one up from it), open_browser (yes) and extra (a dictionary of more for the authorization URL, as "access_type" is "offline"). Tokens are a record: access_token, token_type, refresh_token, scope, id_token and expires_at (seconds since 1970), each nothing when the provider didn't send it, and fields, everything it sent. A provider that says no is a fail with with what it said, as "the provider said invalid_grant: the code has expired".
