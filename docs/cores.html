What it's for

Work on every core at once, as Python's multiprocessing does: a list's items, each given to a function, by copies of this program, each a process of its own, so each has a core to itself. A task (start) shares the program's one turn at a time; these don't.

use "cores.folio" as cores
to slow_square with n
    ... a lot of work ...
    return n * n
end
say cores's each_at_once(slow_square, list of 1, 2, 3, 4, 5, 6, 7, 8)   # [1, 4, 9, 16, 25, 36, 49, 64]

each_at_once gives what the function gave for each item, in the items' order, shared out among as many copies as there are cores (or each_at_once_on(n, ...) for n) in turn: with 4, the 1st, 5th, 9th, ... to the first, the 2nd, 6th, 10th, ... to the second, so each gets as much of a list whose items take longer and longer. Each copy starts the program again, with arguments of its own, and runs it to the same each_at_once, where it does its part and stops; an each_at_once before that one gives it what it gave the program, without doing it again. So what comes before runs in each copy too, and must come to the same each_at_once there: input asked for, or random numbers that change which, can't. A line cores's work_here(slow_square) after the functions is where a copy does its part for slow_square at once, and nothing after it runs in the copy.

A part and what it gives go through files, with save and load, so they're numbers, text, yes and no, nothing, lists, records and dictionaries. A mistake in a part is a fail with that says what the copy said. In a part, each_at_once does its items there, one after another; and so does each_at_once where there are no processes to start (the playground, or the JavaScript engines), giving the same.

Built with --allow-libraries (to start the copies), --allow-read and --allow-write (for their files).
